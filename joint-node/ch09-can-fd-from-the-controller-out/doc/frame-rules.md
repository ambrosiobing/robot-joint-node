# Frame rules: the length code, and which frames are legal

Generated by `python tools/gen_frame_vectors.py --table`. Do not edit by hand.

The controller carries a four bit code, not a length. The code is not the
length above 8, and the same code means different things in the two formats:
a classic frame has no length above eight and reads every code above 8 as 8.

A codec that gets this wrong does not fail loudly. It moves the right bytes
with the wrong count, or the wrong bytes with the right one.

| Code | Classic reads | Flexible-data reads |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 1 | 1 |
| 2 | 2 | 2 |
| 3 | 3 | 3 |
| 4 | 4 | 4 |
| 5 | 5 | 5 |
| 6 | 6 | 6 |
| 7 | 7 | 7 |
| 8 | 8 | 8 |
| 9 | 8 (clamped) | 12 |
| 10 | 8 (clamped) | 16 |
| 11 | 8 (clamped) | 20 |
| 12 | 8 (clamped) | 24 |
| 13 | 8 (clamped) | 32 |
| 14 | 8 (clamped) | 48 |
| 15 | 8 (clamped) | 64 |

| Frame | Legal | Code |
|---|---|---|
| classic, 8 bytes | yes | 8 |
| flexible-data, 64 bytes, no rate switch | yes | 15 |
| flexible-data, 64 bytes, rate switch | yes | 15 |
| REFUSE, classic cannot carry 12 bytes | no | n/a |
| REFUSE, 9 bytes has no code in either format | no | n/a |
| REFUSE, the rate switch without the format | no | n/a |
| REFUSE, 65 bytes is past the largest code | no | n/a |
